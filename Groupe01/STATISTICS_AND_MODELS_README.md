# Statistics and Diagrams Guide

This document explains how the statistics, charts, retrieval results, and
model-based values used in this project are produced.

## Short answer

No statistical model was created and trained from scratch in this project.
The project uses pretrained models plus deterministic processing written in
Python.

The pretrained models are used for:

- image and caption embeddings;
- object detection in the optional `03b_detect_objects` workflow;
- retrieval;
- caption-quality evaluation through CIDEr;
- text encoding used by Sentence-BERT.

The project code calculates the dataset statistics, figures, thresholds,
retrieval metrics, confidence intervals, hypothesis tests, and FAISS/HNSW
performance measurements.

## Data generation pipeline

| Stage | Notebook or script | Main operation |
|---|---|---|
| Dataset annotations | `00_download_annotations.ipynb` | Downloads MS COCO annotations. |

| Image download | `01b_download_images.ipynb` | Downloads the images belonging to the frozen splits. |
| Image preprocessing | `02_preprocess_images.ipynb` | Audits images, normalizes RGB images, resizes them, and calculates image measurements. |
| Leakage repair | `02b_dedup_repair.ipynb` | Removes exact and near duplicates shared across splits. |
| Captions and metadata | `03_captions_metadata.ipynb` | Cleans captions and derives object, size, colour, context, and spatial metadata. |
| Optional detection | `03b_detect_objects.ipynb` | Uses a pretrained DETR model to produce predicted detections. |
| Embeddings and indexes | `04_embeddings_index.ipynb` | Loads pretrained vision and text models, creates embeddings, and builds FAISS indexes. |
| Exploratory statistics | `05_eda.ipynb` | Calculates descriptive statistics and writes the 11 EDA figures and `artifacts/eda/stats.json`. |

## Models used

### CLIP ViT-B/32

Loaded from its pretrained Hugging Face checkpoint in
`04_embeddings_index.ipynb`. The project uses its image encoder for image
embeddings and its text encoder for caption embeddings. No CLIP weights are
trained in this repository.

### SigLIP Base Patch16

Loaded from its pretrained checkpoint in `04_embeddings_index.ipynb`.
SigLIP is the primary encoder in release `g1-v1.1`. The project uses its image
and text encoders to create the embeddings and retrieve captions. No SigLIP
weights are fine-tuned or trained by this project.

### DINOv2-small

Loaded from its pretrained checkpoint in `04_embeddings_index.ipynb`. The
CLS token is used as the image representation. This project does not train or
fine-tune DINOv2.

### Sentence-BERT

`all-MiniLM-L6-v2` is loaded by `04_embeddings_index.ipynb` through
Sentence-Transformers. It creates text embeddings for sentence-level caption
representation. The project does not train this model.

### Optional pretrained DETR

`03b_detect_objects.ipynb` may run pretrained DETR to produce predicted object
detections. Its output is optional. The frozen val/test metadata used for the
reported results comes from COCO ground-truth annotations; it is not created
from predicted DETR detections.

### CIDEr evaluation

`pycocoevalcap.cider` is used to calculate CIDEr. The implementation does not
train a caption model. For each query, project code compares one retrieved
caption with the five ground-truth captions in
`artifacts/tables/eval_refs_val.jsonl` or
`artifacts/tables/eval_refs_test.jsonl`.

### Model definitions used by the experimental figures

- **CLIP ViT-B/32 (`openai/clip-vit-base-patch32`)**: a pretrained vision-language
  model that maps images and text into a shared embedding space. Its image and
  text representations are used for retrieval comparison.
- **SigLIP Base Patch16 (`google/siglip-base-patch16-224`)**: a pretrained
  vision-language model that uses sigmoid-based image-text training. Its image
  and text representations are used for the selected retrieval configuration.
- **DINOv2-small (`facebook/dinov2-small`)**: a pretrained self-supervised
  vision model. The CLS token represents the image; no text encoder is used.
- **Sentence-BERT (`sentence-transformers/all-MiniLM-L6-v2`)**: a pretrained
  sentence encoder for 384-dimensional text embeddings. It is stored in the
  release but is not used to generate the report encoder-comparison results.

## Retrieval and experimental results

### How candidate captions are retrieved

`scripts/compare_encoders.py`:

1. Loads validation or test query embeddings created by the pretrained encoder.
2. Loads the 10,000-vector image database or 50,000-vector caption database.
3. Uses normalized inner product in NumPy to find the nearest results.
4. Uses the first retrieved KB caption as the image-to-text prediction.
5. For image-to-image retrieval, uses the caption attached to the retrieved KB
   image.
6. Applies the project-created relevance rule: query and retrieved classes
   must share at least one COCO object class.

Embedding cosine search is therefore not a learned ranking model. The only
knowledge used comes from the pretrained embeddings, deterministic nearest-
neighbour search, and the COCO captions/metadata.

### Recall and precision

For Recall@K and Precision@K, the script treats a result as relevant when its
metadata shares at least one object class with the query image. Queries with
no object metadata are excluded.

Recall@K, Precision@K, and MRR are calculated directly in
`scripts/compare_encoders.py`, not generated by a trained classifier.

### CIDEr

Each predicted retrieved caption is compared with the five COCO reference
captions for the query image. The script reports the mean CIDEr across 100
queries. The random-caption baseline uses a fixed NumPy seed of 42 to select
one caption per query.

### Encoder comparison chart

`reports/figures/encoder_comparison_val.png` is created by
`scripts/compare_encoders.py` from the frozen validation CSV. The chart plots
the CIDEr and MRR values from `reports/tables/encoder_comparison_val.csv`. It
does not retrain or create a model.

### Statistical validation

`06_select_config.ipynb` calculates:

- 10-fold cross-validation CIDEr means and standard deviations;
- 95% bootstrap confidence intervals with 2,000 image resamples;
- paired Wilcoxon signed-rank tests against the best configuration;
- Jaccard class-at-top-1 values.

These procedures evaluate observed validation scores. No parameter estimation
or encoder training is performed.

## FAISS and HNSW

FAISS stores the already-created pretrained-model embeddings. It does not
create new embeddings or train the vision/text models.

- `IndexFlatIP`: exact normalized inner-product search.
- HNSW: approximate search over the same vectors.
- `M=32`
- `efConstruction=200`
- `efSearch=64`

HNSW Recall@10 and latencies are measured by the indexing code.

The report distinguishes two latency measurements:

- FAISS/index-report latency for the stored HNSW and flat FAISS indexes;
- exact chunked NumPy-search latency for the encoder comparison script.

They are not directly interchangeable because they use different search
implementations and code paths.

## Preprocessing statistics

Image statistics in `02_preprocess_images.ipynb` are calculated directly:

- size after preprocessing;
- aspect ratio;
- RGB conversion;
- brightness;
- contrast;
- colourfulness;
- sharpness;
- dominant colours;
- perceptual hash;
- exact and near-duplicate flags.

These values do not come from a pretrained image classifier. Pixel
measurements are calculated in project code.

## Frozen vs. reported values

The project separates:

- **source data**: COCO images, annotations, and captions;
- **generated metadata**: project-calculated counts and relations;
- **pretrained representations**: CLIP, SigLIP, DINOv2, and SBERT embeddings;
- **search systems**: exact NumPy search, FAISS, and HNSW;
- **evaluation results**: retrieval metrics, CIDEr, bootstrap intervals, and
  Wilcoxon tests;
- **frozen artifacts**: files whose hashes are recorded in
  `artifacts/manifest.json`.

Changing source data, preprocessing, embeddings, or retrieval code requires
running the pipeline again and creating a new release. The frozen release is
not modified in place.

## Important limitations

- No image-caption generation model is trained.
- No CLIP, SigLIP, DINOv2, Sentence-BERT, or CIDEr model is fine-tuned.
- Retrieval does not learn a ranking function.
- COCO ground-truth annotations are used as oracle metadata for frozen
  validation/test evaluation.
- Optional predicted detections do not replace these ground-truth values.
- Spatial relations are bounding-box geometry, not semantic scene graphs.
- Caption colour/size/material/state/shape attributes come from fixed lexical
  rules and can miss or mislabel language.
- The frozen validation and test samples contain 100 images each, so
  statistical uncertainty is relatively large.
